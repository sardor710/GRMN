# Legacy migration: extraction and isolated rehearsal

Scope: Tasks 06–07 of the PostgreSQL XL plan. Application reads/writes remain on their existing adapters. These tools do not activate accounts, publish imported content, contact providers, or perform a production cutover.

## Read-only extraction

From the existing backend worktree, with Node 24 and installed dependencies:

```powershell
npm run db:import:dry-run -- --output temp/backend-next-three/06-current-source
npm run db:import:dry-run -- --archive temp/backend-next-three/06-current-source
```

Choose a new output directory for each new export. Existing `snapshot.json` files cannot be overwritten. Exit **0** means validation has no quarantined rows; **2** means the report contains explicit quarantine; **1** means execution/integrity/argument failure. No database URL is read or connection opened. Standard output contains aggregate counts, issue codes and checksums only. A nonzero exit is not permission to change/approve source facts.

The exporter reads source bytes and a TypeScript AST, never imports CMS getters, seed generators or React components. Current persisted JSON has precedence. The Task 01 static-definition inventory is followed through local named imports/re-exports, including the moved `public-products.ts` literals. Resolved definitions are deduplicated; unavailable/cyclic/computed expressions retain source spans and explicit blockers. Every `src` code/data file is checksummed and copied under `originals/` with an inert `.snapshot` suffix so TypeScript/lint do not discover it as application code; every public asset is checksummed without moving/replacing it. Other editorial literals remain version controlled. FusionCMS and unsaved browser localStorage are outside the discovered server-source boundary.

The output is restricted to the workspace's ignored `temp/` tree. An empty directory is reserved exclusively; linked/reparse-point descendants are rejected. Windows replaces the DACL with the verified owner's SID alone, including removal of other principals' explicit grants; POSIX directories/files use 0700/0600. Original **buffers** retain exact bytes, including invalid UTF-8. `snapshot.json` and its completion marker publish only after the expected original inventory and hashes are verified. Readers reject incomplete or altered backups. Interrupted exports require a new output directory. **`originals/` contains original credentials and personal data** solely as a restricted recovery snapshot. Never add it to Git, serve it, or send it with a review package. Sanitized `snapshot.json` recursively excludes recognized credential fields/aliases; `redactions` records paths, never values. Unknown business fields remain intact. These rules are field classification, not a claim to identify credentials inside arbitrary prose.

Artifact **v2** retains exact numeric JSON lexemes alongside the unchanged parsed business fields. Canonical hashes use exact code-unit ordering, including distinct Unicode keys, and SHA-256. IDs derive from namespace/entity/source-key, not randomness or extraction time. Duplicate identities retain distinct occurrence keys and quarantine every colliding record. A changed source or interpretation gets a different artifact checksum and cannot silently reuse an imported namespace. Superseded pre-review v1 exports must be regenerated; they are not accepted silently. SHA-256 detects accidental tampering; it is not a signature or authorization to trust an arbitrary artifact.

## Money, history and disposition

Owner-confirmed persisted CMS product prices/original prices and order prices/totals are KZT major units. Conversion uses the original numeric token (or original decimal string) before integer arithmetic with exponent 2. Negative/nonfinite values, unsupported precision, exponential notation and amounts outside PostgreSQL bigint are rejected. Contrary explicit line-level currency quarantines the order even if its totals happen to match. Source bytes/values remain unchanged. Coupon money, static/accessory prices and lifetime customer totals are not covered by that confirmation.

Every row is importable, quarantined with a blocker, or intentionally retained as version-controlled static content. All three dispositions retain a restricted source record and deterministic mapping during rehearsal. No source row is discarded for being called a seed/demo. Missing assets/references, malformed dates, duplicates, unresolved monetary semantics and unsupported static computations remain open issues. No run automatically approves quarantine.

Contacts become provisional, unclaimed profiles; no login/verification/consent is inferred. Legacy staff records require controlled bootstrap and remain restricted. Historical paid/delivered labels are preserved in source evidence. Imported orders are `legacy_incomplete`, with `legacy_unknown` payment mode, unasserted payment/fulfillment state and normalized line evidence in their restricted summary. No capture, refund, shipment, order event, synthetic item-level tax/discount allocation or redemption is invented. Historical coupon usage is a separate baseline, not fabricated redemption rows. Content imports are unpublished drafts pending publishing/sanitization review.

## Recovery boundary

Keep the existing source and migrations 0000–0005 unchanged. A source/validation failure needs no business-data rollback: extraction is read-only. Do not reset/reseed the checkout or remove another task's receipt directory. Preserve private source snapshots until the unfinished XL migration/recovery plan no longer needs them. Production import, source merge/reconciliation approval, publication, ownership linking, stock activation and cutover require their later explicit gates.

## Disposable local import and reconciliation

```powershell
npm run db:import:rehearse -- --archive temp/backend-next-three/06-current-source --output temp/backend-next-three/07-current-staging
```

This command creates a **new disposable local PostgreSQL cluster**, applies the existing reviewed migrations, imports the checked archive, replays it, reconciles it, writes a protected row snapshot and stops/removes only its own cluster. It never loads `.env.local` or accepts an external database URL. Use a new output directory. Exit 0/2/1 has the same success/quarantine/error meaning as dry run. Synthetic fixtures use separate namespaces and clusters from the current-source rehearsal.

The underlying `importSnapshot(pool, snapshot, { offline: true, batchSize })` API requires an explicitly provided pool and a one-writer offline boundary. Normal app startup/build never imports. Batches are 1–500 records (50 by default), in FK dependency order. Archive rows, mapping keys, issue rows, targets and checkpoint commit together. A per-namespace advisory lock serializes importers. Deferred snapshot seals are checked before receipt fingerprints are captured. Interrupted/failed batches leave the preceding checkpoint resumable; finished run certificates are immutable. Replays inspect source and target fingerprints, never overwrite staff/live edits or silently recreate deleted target/child rows. A changed namespace source checksum **or interpretation checksum** raises `SOURCE_CHANGED`; there is no automatic merge mode.

Every source record has a restricted `legacy_source_records` row and unique `legacy_id_map` key. The stored `legacy-record-v2` envelope contains sanitized `data` plus `numberLexemes`. Importable rows map to normalized targets; quarantined/static-retained rows map to their archive record. Exceptional invalid Unicode/NUL payloads use reversible `canonical-json-base64-v1` encoding inside `data` because PostgreSQL JSONB cannot store them directly. Unsafe issue paths use reversible `encoded-json:` text. Original sanitized JSON/checksums remain exact and blockers stay open. Credential exclusion precedes encoding/storage. Contact ownership, identities, roles, consent, stock balances, captures/redemptions and shipping history are never manufactured.

Products/default variants/KZT prices, provisional contacts/private notes, content drafts/version metadata, restricted legacy order/address summaries, eligible draft percentage promotions with historical usage baselines and legacy audit facts are normalized. Original taxonomy/activities/media references and unmapped fields remain in the complete source/legacy payload pending service/publication/media integration; current raw records are not thereby certified for production use. No fallback product is created from a missing/static record. No legacy order gets invented item-level tax/discount allocations; normalized source unit prices/quantities remain restricted line evidence.

Reconciliation independently compares intended normalized field values and individual line associations, as well as source counts, original fields/lexemes/checksums, mappings, expected issue identities and aggregate fingerprints. Product-owned category/activity/media/relation/attribute/option rows and content-owned links are included; shared external aggregates retain their own service owners. Raw leaf comparisons, normalized comparisons/mismatches and the count of archived-only top-level fields are reported separately. Before resume, the exact committed prefix, bounds, mappings, source checksums, targets and issues must match; a damaged cursor cannot skip records. Unlock/rollback faults discard the pooled session while preserving the original failure.

Financial output distinguishes normalized target totals, known quarantined source totals and unvalued orders. Any mismatch prevents readiness. Open blockers retain `quarantined`, even if all original fields are accounted for. `parityReady` is internal parity evidence; external `ready` additionally requires a completed certificate and a fresh read-only sequence/collision/high-water check, including replay. Original finished certificates remain historical evidence. Rehearsal exit1 reports a mismatch/failure in **any** phase; exit2 is reserved for fully accounted-for quarantine.

Offline sequence adjustment compares all preserved numeric suffixes as integers (including leading zeros), rejects collisions/exhaustion, and advances `order_number_sequence` without lowering its high-water mark. It shares the import connection and works with a pool of one. Because `setval` is nontransactional and ordinary order writers do not share its advisory lock, a true one-writer freeze is mandatory before a persistent-target use. No such use is authorized in this task.

Before schema/business writes, the rehearsal verifies its newly owned loopback cluster identity/path and restricts the cluster directory and descendants to the current owner. Private outputs: `reconciliation.json`, a checked `database.json.snapshot` of all public table rows and migration SQL signatures, and an output-reservation marker. This is an inspectable **logical staging evidence snapshot**, paired with the checked source archive/replayable importer. It is not a production SQL backup, asset-binary backup, PITR archive or timed restore proof; backup/restore qualification remains Task 23. File-based original/public media recovery remains separately required. Do not commit or publish these outputs.
