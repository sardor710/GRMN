## Bugs found during the run

- **Fixed:** single-SKU products created in the admin showed a "Variant" select with the text `null` on `/p/[id]` (`s2-storefront-pdp.png`).
  - Root cause: `src/server/catalog/service.ts` mapped the variant name with `String(v.name)`, so a NULL name became the string "null". `ProductTop` also rendered a one-option select for single-SKU products.
  - Fix: a NULL name now maps to "". A product with one variant shows only its stock state, as products with options already did.
  - After the fix (`s2-storefront-pdp-after-variant-fix.png`): no select, "In stock". Checked on the admin-created product, an imported single-SKU product (1462801) and a 9-variant product (picker unchanged).

## Observations (not fixed, outside this run's scope)

- **Storefront price scale of imported single-SKU products.** Cards show prices such as "249.99 KZT and up" next to the admin-created "149,990.00 KZT". The first import logged "1 amount warning(s)" for each of these products, so this looks like a legacy price-scale issue in the import.
- **Long generated draft SKUs.** "Add the other N as drafts" builds SKUs like `010-04337-00-51-MM-FENIX-9-YE…` from the option labels.
- **Exports card on the dashboard.** It shows "Exports need the export permission" for a staff session older than 15 minutes. This is the fresh-MFA rule for `exports:create`, not a defect.
